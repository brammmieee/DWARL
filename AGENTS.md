# DWARL agent notes

## Running and checking
- Run from the repository root with Webots R2023b and its Python `controller` module available. The Dockerfile uses `cyberbotics/webots:R2023b-ubuntu22.04` and adds `${WEBOTS_HOME}/lib/controller/python:/DWARL` to `PYTHONPATH`; `scripts/run.bash` must be invoked from `scripts/` because it mounts `$(pwd)/..`.
- Hydra entrypoints are `python3 train.py` and `python3 test.py`. Inspect resolved config without starting a simulation using `python3 train.py --cfg job` or `python3 test.py --cfg job`. Example training: `python3 train.py quit_sim=true generate_data=true steps=10000 setup.model.envs=1` (`demo_commands.bash`). Required values are marked `???` in YAML.
- Evaluation needs an existing training run: `python3 test.py generate_data=true setup.model.date=YYYY-MM-DD setup.model.time=HH-MM-SS setup.model.steps=-1 plotter.show=false`. `steps=-1` loads `best_model.zip`; positive steps load `rl_model_<steps>_steps.zip`. Testing and resumed training read the original `outputs/training/<date>/<time>/.hydra/config.yaml` for the environment setup.
- No automated test suite or lint/typecheck configuration is present; focused checks should target the changed code/config. A full train/test invocation starts Webots and is not a quick smoke test.

## Pipeline and gotchas
- `resources/maps/*.pgm`, `resources/paths/*`, and `resources/map_name_lists/*.yaml` feed `utils/data_generator.py` (map/path arrays and sampled init/goal YAML); `utils/webots_resource_generator.py` builds per-map PROTOs and a world. `utils/data_set.py`/`utils/data_loader.py` supply episodes to `environments/base_env.py` -> `environments/webots_env.py`; `utils/wrapper_tools.py` wraps observations/actions/rewards before SB3 PPO in `train.py` or evaluation/plots in `test.py`.
- Set `generate_data=true` when dataset or map inputs change: both entrypoints otherwise consume existing files under `/tmp/DWARL/data_sets/{training,testing}` and `/tmp/DWARL/sim_resources/{training,testing}`. Generation first **deletes** the corresponding old dataset and simulation-resource directories. Hydra changes cwd to timestamped `outputs/{training,testing}/...`; path config uses `${hydra:runtime.cwd}` for the source root.
- Wrapper composition is ordered in `config/setup/create_setup.yaml`; YAML keys in `config/setup/wrappers/*.yaml` must match the Python wrapper class names because `wrap_env` dynamically looks them up. `BaseEnv` leaves action/observation spaces to wrappers and returns zero reward without a reward wrapper. Testing reuses the wrappers saved with the trained model.
- Keep the repo's coordinate conventions when changing observations or actions: SI units; `[x, y]` positions, `[omega, v]` velocities, `[angle, dist]` polar values (README). `DataGenerator.pixel_to_point` converts image coordinates to meters and flips image y.
